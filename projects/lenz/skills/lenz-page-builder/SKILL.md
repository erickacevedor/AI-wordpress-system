# Lenz: Page Builder

**Input:** the page's copy doc (`.docx`) or brief, plus the target slug.
**Output:** `projects/lenz/pages/<slug>/` with `build.py`, `source.docx`,
`<slug>.json`, `widget-classes.json`, `HANDOFF-notes.md`.

Do not hand-write Elementor JSON for Lenz. Every page is generated by its
`build.py` from the shared blocks, so all pages stay identical in structure and
a fix in one block reaches every page.

## Pipeline (run in order)

### 1. Design read
Apply `lenz-design-read`: page kind, reference page, `cat`, scope check, the
one-line read.

### 2. Put the copy where the reader expects it
Copy goes in `pages/<slug>/source.docx`. `tools/docx_outline.py` reads it:

- first heading = the **H1**; the next heading level = **sections** (one block
  each); deeper headings = **items** inside a section;
- paragraphs before the first section = the hero;
- `SEO Title:`, `Meta Description:`, `URL Slug:` lines = the meta;
- `[ Button Label ]` on its own line = a button node;
- inline bold survives as `<b>`; Word comments are kept as notes.

Inspect it before planning: `python3 projects/lenz/tools/docx_outline.py
projects/lenz/pages/<slug>/source.docx`. If you only have a brief, write the doc
in that structure first, and say in `notes` that the copy is not client-approved.

> **Windows:** use `python` instead of `python3` (on some machines `python3` is the
> Microsoft Store stub), and set `PYTHONIOENCODING=utf-8` before printing an
> outline, or the console crashes on curly quotes.

**Word comments are instructions.** They are the team's and the client's layout
notes on the doc ("Trustbar", "4 column cards", "2 columns"). Apply them through
block options (`cols`, the trustbar, `pair` vs `bullets`) and record that you did in
`notes`, the way `pages/heating-maintenance/build.py` does. A comment that
contradicts a ClickUp decision loses; flag it.

**How the hero is assembled** (`_hero()` in `service_page.py`):

- Hero copy = the paragraphs between the H1 and the first section. Some docs put
  the hero under the first section heading instead: set
  `"kicker_from_section0": True` and that section's heading becomes the line under
  the H1 (the kicker) and its paragraphs the hero copy. That section then consumes
  **no** plan entry.
- `"kicker_from_first_bold": True`: a fully bold first hero paragraph becomes the
  kicker. `"hero_paras": N` keeps only the first N hero paragraphs.
- A paragraph starting "Serving ..." becomes the pinned service-area line.
- The **trustbar** is built from the hero when it holds `<b>Label:</b> text` list
  items, a run-on paragraph with 3 or more of them, or a `<b>A</b> · <b>B</b> · ...`
  line; otherwise it uses the default five proofs. `"trust": [...]` overrides it.
- On non-hub pages whose plan has a `checklist`, hero paragraphs after the first
  move into the **first checklist block**. Do not pick `checklist` for a section
  that should not receive them; use `cards`, `bullets` or `prose` instead.

### 3. Write `build.py`
Copy the reference page's `build.py` and change only the `PAGE` dict:

```python
B.reset(0x??000000)   # a seed no other page uses (see "Seeds" below)

PAGE = {
    "slug": "heat-pumps",
    "source": os.path.join(HERE, "source.docx"),
    "title": "Heat Pumps",                      # breadcrumb + WP page title
    "cat": "warm",                              # cool | warm | air | extra
    "accent": "Heat Pump",                      # words of the H1 painted with the gradient
    "cta": "Schedule Heat Pump Service",        # hero + default block CTA label
    "form_preselect": "Heat Pumps",             # one of brand.FORM_SERVICES
    "hero_image": ("lenz-technician-service-call-webp", "<real, specific alt text>"),
    "badge": ("24/7 emergency service", "Local team, real people, day or night."),
    "related_text": "<one sentence for the related-services band>",   # non-hubs
    "plan": [                                   # ONE entry per doc section, in doc order
        ("checklist", {"eyebrow": ("i-flame", "Signs it is time")}),
        ("cards", {"eyebrow": ("i-wrench", "What we fix")}),
        ("values",),
        ("why",),
        ("faq",),
        ("reviews",),
        ("close",),
    ],
    "notes": [],                                # pending assets, doc comments applied, copy you wrote
                                                # (body copy or claims; eyebrows and badges need no note)
}
```

Other keys, used only when needed: `is_hub` (hubs and company pages: no parent
breadcrumb, no related band), `cat_label` + `cat_icon` (company pages), `cta_href`,
`band` / `band_sub` / `no_band` (the emergency band), `trust` (custom trustbar),
the hero keys above, `doc_patches` and `add_items` (below). Block options:
`eyebrow`, `bg`, `icons`, `cols`, `numbered`, `help`, `link`, `links`, `button`,
`id`, `drop`, `tel`, `layout`, `parts` (for `multi`). `"skip"` consumes a doc
section without output (say why in `notes`).

A `"+name"` entry adds a block that consumes **no** doc section, so it has no
title or copy of its own. Use it only for blocks whose options carry everything
they show: today that is `+coupons` (title, lead and images in its options). Do not
use `+reviews`, `+plans` or `+promo` to add a section the doc does not have: they
render an empty heading.

The builder **fails** if the plan does not use every doc section exactly once.
That is intended: never drop doc content silently.

**`form_preselect`** (must be one of `brand.FORM_SERVICES`): AC repair, install and
replacement pages use their own name ("AC Repair", "AC Installation", "AC
Replacement"); hubs use "Air Conditioning" / "Furnace & Heating" / "Indoor Air
Quality"; heating repair and installation use "Furnace & Heating"; every
maintenance page uses "Maintenance"; IAQ services use "Indoor Air Quality"; company
pages leave it out.

**Seeds:** every page needs a unique `B.reset()` seed or element ids collide across
pages. List the ones in use and take a new one:
`grep -rho 'reset(0x[0-9a-fA-F]*)' projects/lenz/pages | sort -u`.

**Copy patches.** `doc_patches` is for content that changed after the doc on that
one page (a ClickUp request for that page). A rule that applies site-wide (a
retired claim, a renamed office) belongs in `FIXES` / `REGEX_FIXES` in
`service_page.py`, so every page picks it up and its HANDOFF lists it; adding one
changes every page, so ask Erick first. `doc_patches` do not appear in the
HANDOFF's "Copy changes" list: mention each in `notes`. If a wording only *might*
break a rule (for example "no trip fees" said about plan members, which is an open
question), do not patch it: flag it in `notes` and ask.

### 4. Media
Images come from `media.json` keys (attachment ids of the site). A new image must be
uploaded to the WordPress media library first and added to `media.json` with its
real id and URL. Use the WebP keys. Every image gets specific alt text. Temporary
photos are acceptable until the client shoot (ClickUp 10/08); say so in `notes`.

### 5. Links and menus
- Internal links come from `brand.L` / `brand.href()`; never type a URL by hand.
- A new page needs its key in `brand.L`. Adding it to the menus is one edit in
  `brand.SERVICES` or `brand.NAV` (mega menu, mobile menu, footer and home read it),
  then rebuild `pages/_theme/build-templates.py`. Only with Erick's yes if the page
  is outside the 26-page scope.

### 6. Build, gate, port
```bash
python3 projects/lenz/pages/<slug>/build.py
python3 scripts/validate-page.py projects/lenz/pages/<slug>/<slug>.json   # must exit 0
python3 projects/lenz/tools/port-css.py   # only if classes or CSS changed
```
`projects/lenz/build-all.sh` does all pages at once. Gate warnings about "same
background" rhythm are expected (bands are CSS-owned), not findings.

### 7. Render check (required)
Import to a **local** install (`build-all.sh --import` with `LENZ_WP_CLI` and
`LENZ_WP`, see the script) and look at 1440, 1024, 768 and 390: no horizontal
scroll, hero and bands match the reference page, every CTA lands on `#contact` or
its stated target. A headless browser screenshot loop is fine.

### 8. Audit
Apply `lenz-page-audit`. Fix the build, never the JSON.

### 9. Deploy
- Local first, always. `build-all.sh --import` overwrites pages by slug; never point
  it at a live site.
- lenz.mysites.io receives work by Erick's push from Local, or by importing the JSON
  with `tools/import-page.php` (WP-CLI) only with Erick's explicit yes for that page.
- After any deploy, purge the Flywheel cache (dashboard, Advanced, Flush cache) or
  the CDN keeps serving the old HTML and CSS version.

### 10. Handoff
`HANDOFF-notes.md` is generated: meta title, meta description, slug, canonical, the
ClickUp fixes that fired, and `notes`. Set the meta in the SEO plugin by hand after
import (the JSON cannot carry it). Commit `build.py`, `source.docx`, the JSON and
the notes together.

## Guardrails

- One H1, from the doc. Root-relative links only. No `display_condition_list`.
- Never edit `<slug>.json` or `lenz-core.css` by hand: rebuild.
- Never invent a block layout inside a page; new shapes follow "Adding a
  component" in `lenz-ui-design`.
- Missing a brand-critical fact (slug, CTA target, which photo, scope)? Ask one
  focused question instead of guessing.
